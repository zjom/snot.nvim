1. INTRODUCTION                                            *snot-introduction*

snot keeps notes as plain text files in Simple Note Format (|snot-format|),
in a notes directory:

  - Daily notes are named after their date, e.g. `20240102.snot`.
  - Other notes are named `{date}__{slug}.snot`, e.g. `20240102__my-idea.snot`.

New notes open in a buffer pre-filled from a template. Nothing is written to
disk until you save, so an abandoned note leaves no file behind.

Tags are metadata flags such as `@work`, written on any line of a note. They
tag the file, heading, list item or table row that owns the line.
|:Snot| `tag` finds where a tag is set with the |snot-picker|.

Notes link to each other with `[[path]]`, where the path is relative to the
notes directory and has no extension, e.g. `[[20240102__my-idea]]` or
`[[daily/20240102#standup|standup]]`. |:Snot| `backlinks` lists the notes
linking to one (requires ripgrep). `gf` on a link opens the note.

Notes are highlighted with tree-sitter, using the `snot` and `snot_inline`
parsers from https://github.com/zjom/tree-sitter-snot. snot registers them
with nvim-treesitter (main branch), so `:TSInstall snot` installs both along
with their queries. Without the parsers, notes are not highlighted.

Requires Neovim 0.11 or later. Run |:checkhealth| `snot` to verify your setup.

2. CONFIGURATION                                          *snot-configuration*

                                                                    *g:snot*
No setup call is needed. To change the defaults, set `vim.g.snot` before the
plugin is first used:
>lua
  vim.g.snot = {
    directory = "~/notes",   -- folder containing notes
    daily_directory = nil,   -- folder for daily notes, see below
    date_format = "%Y%m%d",  -- strftime format for dates in file names
    extension = ".snot",     -- note file extension, including the dot
    open_cmd = "edit",       -- Ex command used to open notes
    templates = { ... },     -- see |snot-templates|
    picker = nil,            -- picker for tags and backlinks, see below
  }
<
`daily_directory` puts daily notes in their own folder inside `directory`,
e.g. `"daily"` means `~/notes/daily`. It must be a relative path without
`..`, since links are relative to `directory`. When unset, daily notes go in
`directory`.

Notes are every file with the note extension under `directory`, in any
folder except hidden ones. They get the `snot` filetype.

                                                                *snot-picker*
`picker` chooses how tag searches and backlinks are shown: `"telescope"`, `"fzf-lua"`,
`"snacks"`, `"mini.pick"`, `"quickfix"` or `"select"` (|vim.ui.select()|).
When unset, the first of telescope, fzf-lua, snacks and mini.pick that is
installed is used (snacks and mini.pick once set up), else `"select"`.
It can also be a function called with the places to pick from and
`{ prompt }`; choosing a tag then uses |vim.ui.select()|:
>lua
  picker = function(items, opts)
    -- items: list of { path, lnum?, col?, text? }
  end
<
                                                                *snot.setup()*
Alternatively call `require("snot").setup(opts)` with the same table. Each
call starts again from the defaults, so options don't accumulate.

Invalid options are reported and the defaults are used instead.

3. COMMANDS                                                    *snot-commands*

                                                                       *:Snot*
:Snot new [title]       Create a note. Prompts for a title if none is given.

:Snot daily [date]      Open a daily note, creating a buffer for it if it
                        doesn't exist. [date] is `today` (default),
                        `yesterday`, `tomorrow`, an offset such as `-3` or
                        `+1`, or a literal date in `date_format`.
                        Existing daily notes are offered as completions.

:Snot dir               Open the notes directory.

:Snot tag [tag]         Find every place [tag] is set, e.g. `work` or
                        `@work`, with the |snot-picker|. Without a tag,
                        pick one from all tags first.

:Snot backlinks [note]  Find links to [note], a link path such as
                        `20240102__my-idea` or `daily/20240102`, or to the
                        current note. Uses the |snot-picker|. Only saved
                        notes are searched.

`new`, `daily` and `dir` accept window modifiers, which open the note in a
split instead of using `open_cmd`:
>vim
  :vertical Snot daily yesterday
  :tab Snot new Meeting notes
  :botright Snot dir
<

4. MAPPINGS                                                    *snot-mappings*

snot defines no key mappings. These <Plug> mappings are available:

  *<Plug>(snot-new)*     Prompt for a title and create a note.
  *<Plug>(snot-daily)*   Open today's daily note.
  *<Plug>(snot-dir)*     Open the notes directory.
  *<Plug>(snot-tag)*     Pick a tag, then a place it is set.
  *<Plug>(snot-backlinks)* Find notes linking to the current one.

Example:
>lua
  vim.keymap.set("n", "<leader>pd", "<Plug>(snot-daily)")
  vim.keymap.set("n", "<leader>pn", "<Plug>(snot-new)")
<

5. LUA API                                                          *snot-api*

All functions are on `require("snot")`. Functions that open a note return
`bufnr, path` on success, or `nil, err` after reporting the error.

create_note({opts})                                       *snot.create_note()*
    Open a new note pre-filled from a template. If the note already exists,
    a daily note is opened as-is and any other note gets a unique suffix.

    {opts} fields, all optional:
      - title     (string) required unless `is_daily`
      - content   (string) text for `${content}`
      - tags      (string|string[]) list, or comma/space separated string;
                  each must be a metadata key, e.g. `work` or `@work`
      - template  (string) template name, default `"default"`
      - is_daily  (boolean) create a daily note
      - date      (string) date in `date_format`, default today
      - cmd       (string) overrides `open_cmd` for this call

goto_daily({opts})                                         *snot.goto_daily()*
    Open the daily note for `opts.date` (default today). {opts} may contain
    `date`, `content` and `cmd`. `create_daily()` is an alias.

open_dir({opts})                                             *snot.open_dir()*
    Open the notes directory, creating it if needed. {opts} may contain `cmd`.

directory()                                                 *snot.directory()*
    Absolute path of the notes directory.

config()                                                       *snot.config()*
    The resolved configuration table.

tags()                                                           *snot.tags()*
    All tags used across notes, sorted. A tag is a flag token, `@tag` (or
    `@tag:true`), in any scope. Tokens in code and math are ignored.

notes_with_tag({tag})                                  *snot.notes_with_tag()*
    Full paths of notes where {tag} is set, newest first.

tag_locations({tag})                                    *snot.tag_locations()*
    Every place {tag} is set, as a list of `{ path, lnum, col, text }`,
    newest note first.

find_by_tag([{tag}])                                      *snot.find_by_tag()*
    Pick from the places {tag} is set with the |snot-picker|. Without a
    tag, pick one from all tags first.

backlinks({note}, {on_done})                                *snot.backlinks()*
    Find links to {note} (link path or file path) in saved notes, in the
    background: `[[note]]`, `[[note#anchor]]` and `[[note|label]]`. Links in
    code and math don't count. Calls {on_done} with a list of
    `{ path, lnum, col, text }`, newest note first, or with `nil, err`.

find_backlinks([{note}])                               *snot.find_backlinks()*
    Pick from the notes linking to {note}, default the current note, with
    the |snot-picker|.

6. TEMPLATES                                                  *snot-templates*

`templates` maps names to template strings. `${name}` placeholders are
replaced when a note is created; unknown placeholders become empty.

  `${title}`       note title as typed (the date, for daily notes)
  `${date}`        note date in `date_format`
  `${created}`     today's date in ISO 8601, e.g. `2024-01-02`
  `${tags}`        tags as flags, each preceded by a space, e.g. ` @a @b`
  `${content}`     the `content` option

The cursor is placed at the end of the rendered template. The default
template is:
>
  @created:${created}${tags}

  # ${title}

  ${content}
<
The first line holds file metadata. A title may itself contain inline
syntax, e.g. `:Snot new Kickoff @project:atlas` gives the heading
`# Kickoff @project:atlas`; tokens are left out of the file name.

7. NOTE FORMAT                                                   *snot-format*

Notes are written in Simple Note Format, specified in `NOTE_SPEC.md` in the
plugin's repository. In brief:
>
  @area:work @created:2024-01-02

  # Atlas kickoff @project:atlas @person:[bob, priya]

  Met with Bob about the *new* timeline. See [[projects/atlas#risks]].

  ## Follow-ups @id:follow-ups
  - [ ] Send Bob revised plan @due:2024-01-09 @urgent
    - [x] Find a room
  - [-] Chase old invoice

  | Milestone | Due        | Owner      |
  |-----------|------------|------------|
  | Beta      | 2024-10-31 | @owner:bob |
<
  - `#` to `######` then a space start a heading.
  - `- ` and `1. ` start list items; `[ ]`, `[x]` and `[-]` make tasks.
  - `@key`, `@key:value` and `@key:[a, b]` are metadata. It belongs to the
    heading, list item or table row on that line, or to the file when above
    the first heading. Nothing is inherited.
  - `[[path]]`, `[[path#anchor]]` and `[[path|label]]` link to notes; an
    anchor is an `@id` or a heading's slug. `[[https://...]]` links to URLs.
  - `*bold*`, `_underline_`, `` `code` ``, `$math$`, and ``` and `$$` blocks.
    Code and math are verbatim: nothing inside them is metadata or a link.
  - `\` before punctuation escapes it, e.g. `\@not-metadata`.
